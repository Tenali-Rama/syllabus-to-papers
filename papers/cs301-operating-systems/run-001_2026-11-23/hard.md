## Section D — Numerical Problems (4 questions × 10 marks = 40 marks)

**D1.** Three independent periodic real-time tasks run on one CPU. Deadlines equal periods; context-switch overhead is zero; a job released at time 0 is ready at 0.

| Task | Period T (ms) | Worst-case execution C (ms) |
|---|---|---|
| T1 | 4 | 1 |
| T2 | 5 | 2 |
| T3 | 10 | 3 |

Conventions: under RMS, T1 > T2 > T3 in priority (shorter period = higher priority); the response-time iteration is

```
R = C + Σ⌈R/Tₕ⌉·Cₕ
```

over higher-priority tasks, started from R₀ = C and iterated to convergence; schedulability requires R ≤ T for every task.
(a) Compute the total utilization and compare it with the Liu–Layland bound for 3 tasks, 3(2^{1/3} − 1). Determine whether the bound is exceeded (2).
(b) Run the response-time iteration for T2 and T3 and determine whether the task set is RMS-schedulable despite part (a) (4).
(c) Determine whether the set is EDF-schedulable, and whether both arguments can be true simultaneously (4).
*(M3, 10)*

**D2.** A system has a 32-bit virtual address space, 4 KB pages, and a three-level page table in which one level-1 entry covers 8 bits of the address, one level-2 entry covers 6 bits, and one level-3 entry covers 6 bits, with the remaining 12 bits as page offset.
(a) Determine the number of entries in each level's table and verify the bit split (8 + 6 + 6 + 12 = 32) (3). (b) Split the virtual address 0x004031A4 into its level-1 index, level-2 index, level-3 index and offset (3). (c) TLB hit ratio 80%; TLB lookup 20 ns; one memory access 100 ns; on a TLB miss, the walk needs one memory reference per table level before the actual access. Compute the expected access time (4).
*(M5, 10)*

**D3.** The page-reference string of a process is:

**4, 1, 2, 0, 4, 1, 5, 4, 1, 3, 3, 0, 5**

Conventions: all frames initially empty; demand loading; a load of an empty frame is a fault; FIFO evicts the page loaded earliest.
(a) Trace FIFO with 3 frames and count the faults (3).
(b) Trace FIFO with 4 frames and count the faults. Determine whether Belady's anomaly occurs for this string and justify (3).
(c) Compute LRU fault counts with 3 and 4 frames (2).
(d) Compute Optimal fault counts with 3 and 4 frames and state what the LRU/OPT results say about the anomaly's cause (2).
*(M5, 10)*

**D4.** A system has 24 physical frames and four processes A–D. The working set of each process is 5 pages. Measured state: CPU utilization 20%, paging device (swap) utilization 90%, and each process faults at a rate of 1% of accesses. A memory access costs 100 ns; a page-fault service costs 5 ms.
(a) Determine whether the system is thrashing, using the CPU/paging utilization evidence (3).
(b) Process E with working set 5 pages is admitted. Determine whether the frame budget can still cover all working sets (2).
(c) What-if: the swap area becomes full and the OS responds by suspending (swapping out) one whole process. Determine whether thrashing can be expected to resolve, with numbers (3).
(d) Compute the effective memory access time at the 1% fault rate, and re-compute it if extra memory reduces the rate to 0.1% (2).
*(M5, 10)*

### Section B
- **B1.** e.g. the guest runs in deprivileged mode so the instruction traps (VM exit / trap-and-emulate) and the hypervisor emulates it.
- **B2.** asynchronous kills a thread at an arbitrary point; deferred lets it run to a cancellation point; deferred is safer.
- **B3.** many short jobs queue behind one long job; worst in FCFS (head-of-line blocking) and fixed-priority-without-aging (low priority never runs).
- **B4.** both spin-wait (busy waiting) when the lock is held, burning CPU and allowing unbounded waiting; add a wait queue/semaphore or the bounded-waiting mutex pattern.
- **B5.** WS = the set of pages referenced in the last Δ references; PFF raises a process's allocation when its fault rate exceeds an upper bound and sheds frames when it falls below a lower bound.
- **B6.** advantage: O(1) file-name search; drawback: hash destroys ordered listing and handles hierarchies poorly without extra structure.
- **B7.** bitmap: contiguous search is a cheap in-memory scan; linked list: may require reading many blocks scattered on disk — expensive.

### Section C
- **C1.** (a) bounded request queue, acceptor enqueues, workers dequeue, fetch, respond; (b) `fork()` replicates only the calling thread; the child holds clones of mutexes possibly locked by other threads (danger) — `exec()` destroys all other threads; (c) yes, arbitrary-point cancellation while holding a mutex leaves it locked → corruption; deferred cancellation checks only at safe cancellation points.
- **C2.** (a) wait-for graph: cycle ⇒ deadlock; multi-instance: scan for processes with request ≤ available, release their allocations, repeat; a process that never completes is deadlocked. (b) terminate processes (loses their work) / preempt resources and roll back victims (recomputation cost). (c) no — a total order forbids a cycle in the resource graph, so deadlock cannot form.
- **C3.** (a) type/device/size, timestamps, link count, and 12–15 pointers including indirects; (b) root inode → lookup "a" → directory block entries (name, inode#) → inode of a → ... → file inode; (c) scan/set bitmap bit, decrement free count, write pointer into the inode, then the data write.

### Section D
- **D1.** (a) `U = 1/4 + 2/5 + 3/10 = 0.95 > 3(2^{1/3} − 1) ≈ 0.780` → **bound exceeded**. (b) T2: `R₀=2 → 2 + ⌈2/4⌉·1 = 3 → 2 + ⌈3/4⌉·1 = 3 = R* = 3 ≤ 5`. T3: `R₀=3 → 3 + ⌈3/4⌉·1 + ⌈3/5⌉·2 = 6 → 3 + ⌈6/4⌉ + ⌈6/5⌉·2 = 9 → 3 + ⌈9/4⌉ + ⌈9/5⌉·2 = 10 → 3 + ⌈10/4⌉ + ⌈10/5⌉·2 = 10 = R* = 10 ≤ 10` (equality allowed: a job finishing exactly at its deadline meets it). R1 = 1 ≤ 4. **RMS-schedulable**; a full hyperperiod simulation (H = 20) shows no deadline misses. (c) EDF: schedulability test for EDF on one processor is U ≤ 1 and 0.95 ≤ 1 → **EDF-schedulable**. Both can be true: the Liu–Layland bound is only sufficient for pure fixed-priority RMS, not necessary; dynamic-priority EDF exploits deadlines directly.
- **D2.** (a) level 1: 2⁸ = 256 entries; level 2: 2⁶ = 64; level 3: 2⁶ = 64; offset 2¹² = 4096 = page size ✓; 8+6+6+12 = 32 ✓. (b) 0x004031A4 = 0000 0000 | 01 0000 | 00 0011 | 0001 1010 0100 → L1 index = 0x00 (0), L2 index = 0x10 (**16**), L3 index = 0x03 (**3**), offset = 0x1A4. (c) hit: 20 + 100 = 120 ns; miss: 20 + 3×100 + 100 = 420 ns; EAT = 0.8×120 + 0.2×420 = 96 + 84 = **180 ns**.
- **D3.** (a) FIFO 3 frames: faults at 4,1,2,0,4,1,5,3,0 → **9 faults** (final frames: 5,3,0). (b) FIFO 4 frames: faults at 4,1,2,0,5,4,1,3,0,5 → **10 faults**. Yes — 10 > 9 with *more* frames, which is precisely Belady's anomaly for this string. (c) LRU: 3 frames → **10**, 4 frames → **8**. (d) Optimal: 3 frames → **7**, 4 frames → **6**. LRU and OPT both improve monotonically with more frames; the anomaly is a property of FIFO's eviction order, not of the string itself.
- **D4.** (a) paging device 90% busy while CPU only 20% busy is the classic thrashing signature: the machine spends its time servicing faults → **thrashing**. (b) required frames 5×5 = 25 > 24 → the working sets cannot all be resident; more faults will follow → **cannot cover them**. (c) suspend one process: remaining demand 4×5 = 20 ≤ 24 → every remaining working set fits, fault rate falls, CPU utilization rises → **thrashing resolves** (20 frames resident vs 24 available leaves slack). (d) EMAT = 0.99×100 + 0.01×5,000,000 = 99 + 50,000 = **50,099 ns ≈ 50.1 µs**; at 0.1%: 0.999×100 + 0.001×5,000,000 = 99.9 + 5,000 = **5,099.9 ns ≈ 5.1 µs** — a 10× reduction from a 10× fault-rate cut.
